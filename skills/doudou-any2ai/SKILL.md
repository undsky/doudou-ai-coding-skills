# Any2AI：任意文件转 AI 友好文本

**本技能不自己执行转换，只做分派。** 你负责识别文件类型、挑参数、调用对应技能、汇总结果；
实际转换由下面三个技能各自的脚本完成。

## 依赖的三个技能

| 文件类型         | 调用技能      | 产出                | 仓库                     |
| ---------------- | ------------- | ------------------- | ------------------------ |
| 🎙️ 音视频        | `doudou-stt`  | 字幕 / 逐字稿       | `undsky/doudou-stt-skill` |
| 📄 文档 & 电子书 | `doudou-doc`  | Markdown            | `undsky/doudou-doc-skill` |
| 🖼️ 图片 & PDF    | `doudou-ocr`  | 识别出的文字        | `undsky/doudou-ocr-skill` |

三个都是独立技能，需要各自安装：

```bash
npx skills add undsky/doudou-stt-skill
npx skills add undsky/doudou-doc-skill
npx skills add undsky/doudou-ocr-skill
```

要用的那个没装上，就告诉用户装哪一个，**不要自己写脚本、也不要直接打后端 webhook 替代** ——
参数契约、鉴权头、错误分级都在那些技能里，绕过去只会拿到更难查的报错。

## 第零步：确定要转哪些文件

| 用户怎么说                                     | 转什么                                               |
| ---------------------------------------------- | ---------------------------------------------------- |
| 给了文件路径                                   | 就转这些文件                                         |
| 给了目录                                       | 递归扫这个目录下的所有文件                           |
| **没指定**（如“转一下资料”“读下附件说了什么”） | **默认转项目根目录下的 `resources/data/`**，递归扫描 |

项目根从当前工作目录往上找，遇到 `.agents` / `.claude` / `.git` 就认作项目根。

```bash
# 用户没指定 → 先看看 resources/data/ 里有什么
find resources/data -type f -not -name '.*' -not -name '.gitkeep'
```

扫出来的文件按下方 **第一步** 分类型处理，不在支持列表里的跳过。

`resources/data/` 不存在或者是空的（只有 `.gitkeep`），**不要自己建目录、也不要转别的
地方的文件** —— 直接告诉用户这个目录是空的，问他要转哪些文件，或者让他把文件放进
`resources/data/`。

## 第一步：按扩展名分派

先看扩展名，决定调哪个技能。别凭文件名猜内容，扩展名是唯一可靠的依据。

| 文件类型         | 扩展名                                                                                                                                        | 调用技能     |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| 🎙️ 音视频        | `.mp3` `.wav` `.m4a` `.aac` `.flac` `.ogg` `.opus` `.mpeg` `.mpga` `.mp4` `.mov` `.mkv` `.avi` `.webm` `.flv` `.wmv` `.m4v` `.ts` `.3gp`       | `doudou-stt` |
| 📄 文档 & 电子书 | `.doc` `.docx` `.docm` `.xls` `.xlsx` `.xlsm` `.xlsb` `.ppt` `.pptx` `.pptm` `.pps` `.ppsx` `.pot` `.epub` `.rtf` `.csv` `.odt` `.ods` `.odp` | `doudou-doc` |
| 🖼️ 图片 & PDF    | `.png` `.jpg` `.jpeg` `.webp` `.bmp` `.tif` `.tiff` `.gif` `.pdf`                                                                              | `doudou-ocr` |

**不在列表里的扩展名直接跳过**，处理完后总结时列出跳过的文件（带原因：格式不支持）。
不要硬塞给某个技能 —— 走错技能的报错指向“探测不到音轨”这类无关方向，反而难查。

`.pdf` 归 `doudou-ocr`：它对上传的 PDF 会先试文字层直抽（不到 1 秒、一字不差），
抽不出才降级 OCR，覆盖了扫描件和正常导出的两种情况。只有用户明确要 PDF 的
**Markdown 结构**（标题层级、表格）时才改调 `doudou-doc`。

一次给多个文件，先按类型分组 —— 不同类型分别调用，所有文件逐个转换。

## 调用子技能的三条铁律

**一、文件路径由本技能给，不让子技能自己找。** 三个技能都有“用户没指定就扫
`resources/data/`”的默认行为。你已经在第零步扫过并分好组了，调用时必须把具体路径显式
传进去，否则它们会各自重扫一遍、把不属于自己的类型也捞进去。

**二、输出路径由本技能给。** 三个技能的默认产物目录各不相同（`resources/stt/`、
`resources/doc/`、`resources/ocr/`），而本技能的产物统一进 `resources/any2ai/` ——
下游 `doudou-product` 就是从那里取材的。所以**每次调用都要显式带 `-o`**，见
**产物存哪里**。

**三、一次调用只处理一个类型组。** 别把三类文件塞进同一次调用。

调用方式：用 Skill 工具调对应技能，参数里写清要转的文件路径、`-o` 产物路径，以及下面
挑好的参数。子技能自己的 SKILL.md 会说明脚本怎么跑，不用你拼命令行。

## 产物存哪里

| 场景                   | 怎么做                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **默认**（未明确指定） | 输出到项目根的 `resources/any2ai/`，文件名追加 `-年月日时分秒`（如 `-20260819153012`），执行前告知用户将写入该位置 |
| 自定义目录             | 用户明确给出了存放路径（如“存到 out/”），按用户指定路径保存，目录不存在会自动建                                     |
| 不用保存               | 用户明确说明“不用存”或“我就看看内容”，则不传 `-o`，正文留在对话里                                                   |

产物扩展名跟着子技能的输出格式走：字幕 `.srt`（或 `.txt` / `.vtt` / `.json`）、
文档 `.md`、OCR `.txt`。

## 音视频 → 调 doudou-stt

传给它：文件路径、`-o` 产物路径，加上下面这几个值得花心思的参数。

| 参数                | 怎么定                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `--language` / `-l` | **值得花心思填。** `auto` 会先跑一次语种检测，慢且偶尔认错（中文认成粤语/日语见过）。听得出是中文就填 `Chinese`，英文填 `English`       |
| `--prompt` / `-p`   | **中文素材必传** `以下是普通话的句子。` —— 不传不是标点略差，而是整篇没有标点。有专有名词（人名、产品名、术语）也塞这里，能提高命中率   |
| `--format` / `-f`   | 用户要字幕文件 → `srt`（默认）；要拿内容去做摘要、翻译、写文案 → `txt`，省掉满屏时间码；要做卡点剪辑、逐词对齐 → `json`（词级时间戳）   |
| `--task`            | 只有用户明确要“翻成英文”时才用 `translate`。要译成其他语言，先 `transcribe` 拿原文再自己译                                              |
| `--model`           | **留空。** 服务端只预置了 medium 权重，换别的会触发模型下载，首次极慢                                                                  |
| `--threads`         | **留空。** 显式传值会覆盖掉服务端 `.env` 的配置                                                                                        |

**开跑前先告诉用户大概要等多久** —— 耗时约为音频时长的 0.72–0.95 倍：30 秒口播约 25 秒，
1 小时会议录音约 45–55 分钟。别让人以为卡死了。

文件走上传，**上限 100MB**。超了别硬试（后端不回 413，只会干等到超时），先抽音轨压一版：
`ffmpeg -i big.mp4 -vn -ac 1 -ar 16000 small.wav` —— 纯语音识别不需要视频轨和高码率。

## 文档 & 电子书 → 调 doudou-doc

传给它：文件路径、`-o` 产物路径。

| 参数                 | 怎么定                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| `--format` / `-f`    | **留空。** 按文件内容判定比扩展名可靠。填错不报错而是静默出乱码，拿不准就别填                    |
| `--max-chars` / `-m` | 大文件必传。1.8M 的 CSV 会转出 2.3M Markdown，直接喂模型会爆上下文。截断只影响返回内容，落盘是全文 |
| `--no-content`       | 想先探大小再决定要不要读全文时用，只回落盘路径与字数                                            |
| `-r`                 | 只在给目录且要递归子目录时传                                                                    |

很快 —— 纯 CPU 解析、不联网、不加载模型：小文件约 51ms，1.8M / 5 万行 CSV 约 292ms。
不用像转字幕那样预告等待时间。

## 图片 & PDF → 调 doudou-ocr

传给它：文件路径、`-o` 产物路径。

| 参数            | 怎么定                                                                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `--lang` / `-l` | 默认 `ch` 是**中英混排**模型，中文图、纯英文图都能认。纯英文素材填 `en` 可略微提准；日 `japan`、韩 `korean`、繁体 `chinese_cht` 等**必须显式指定** |
| `--format` / `-f` | `txt`（默认）给正文；要知道走了哪条识别路径、多少行多少页才用 `json`                                                         |

一次请求只用一个语种模型 —— 中日混排没法一次识全，分别跑两遍再拼。

**耗时要预告**：图片约 5–10 秒/张（其中约 5 秒是固定的模型加载开销，图小也省不掉）；
图片型 PDF 约首页 7 秒 + 每多一页 4 秒；带文字层的 PDF 走直抽不到 1 秒。批量是串行的，
总耗时按张数累加。

手上只有带文字层 PDF 的 URL 时，**先下载到本地再传** —— 传 URL 会跳过文字层直抽，
实测漏行还慢十几倍。

## 出错了怎么办

子技能的报错都带 `阶段`（`stage`）字段，指向问题归属，各自的 SKILL.md 里有完整对照表。
**把`阶段`和`详情`如实转述给用户** —— 这些信息是专门为了能被诊断才做出来的，含糊成
“转换失败了”就白费了。

本技能这一层只管两件事：**该不该改道**，和**哪些不是故障**。

| 子技能返回                             | 这一层怎么处理                                                                                   |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `doudou-doc` 报 `unsupported`（415）   | 文件**没有文字层** → **改调 `doudou-ocr`**。不是故障，也别改 `--format` 硬试                     |
| `doudou-doc` 报 `garbled`              | 转出来大半是替换字符（无 ToUnicode 表的 CJK PDF）→ **改调 `doudou-ocr`**                         |
| `doudou-doc` 成功但产物为空            | anydoc 对残缺文档“尽量恢复”，转不出也退 0。**文档里有图就是扫描件 → 改调 `doudou-ocr`**；确实没内容就如实说“这个文档没有可提取的文字”，别当成“文档内容就是空的” |
| `doudou-ocr` 的 PDF 结果 `method: paddleocr` | 正常 —— 说明这份 PDF 没文字层，走了 OCR。不用改道                                            |
| `doudou-stt` 报 `nospeech`             | 跑通了但一句话都没识别到：纯音乐、静音、只有环境音。**这不是故障**，如实告诉用户，不要重试        |
| `doudou-ocr` 结果为空但退出码 0        | 后端认为成功、只是没抽出字。先确认语种选对了，再看图是不是太小太淡；必要时放大或提高对比度再试    |
| 任何技能报 `auth`（400 / 401 / 502）   | 是配置问题不是分派问题，见下方 **服务地址与用户标识**。换文件、改道都没用                        |
| 其他阶段                               | 原样转述，不要自己改参数重试 —— 参数不合法（`validate`）重试没意义，服务端故障（`exec` 等）也一样 |

改道时告诉用户为什么改（“这份 PDF 没有文字层，转走 OCR”），别静默换一条路。

## 服务地址与用户标识

**本技能不管配置**，三个子技能各自读自己技能目录下的 `.env`：

| 技能         | 服务地址键名      | 用户标识键名      | 标识必需性         |
| ------------ | ----------------- | ----------------- | ------------------ |
| `doudou-stt` | `DOUDOU_STT_URL`  | `DOUDOU_STT_KEY`  | 取决于部署侧       |
| `doudou-doc` | `DOUDOU_DOC_URL`  | `DOUDOU_DOC_KEY`  | **当前实测必填**   |
| `doudou-ocr` | `DOUDOU_OCR_URL`  | `DOUDOU_OCR_KEY`  | **当前实测必填**   |

优先级都是 命令行 `--base` / `--key` > 环境变量 > **技能目录的 `.env`**。它们只读自己
目录那一份，不向上找项目根 —— 和上面找待转文件的规则不同，别混。

标识走 `X-Uuid` 请求头，值填纯 uuid。报 `auth` 阶段时，让用户把 uuid 填进**对应技能**
目录的 `.env`，或本次用 `--key <uuid>` 传。三个技能的键名互不通用，别把 uuid 填错文件。

服务地址默认都是 `http://localhost:5678`。`https://n8n.undsky.com` 是**另一台实例**，
本地建的 webhook 在它上面不存在（回 404 not registered），别想当然换成公网域名。

## 汇总

所有文件处理完后给用户一份总结：

- 转了哪些文件，各自的产物路径（默认在 `resources/any2ai/`）
- 跳过了哪些，原因（格式不支持）
- 失败了哪些，各自的`阶段`和`详情`
- 改道过的文件说明改道原因（如“扫描件，从 doudou-doc 转到 doudou-ocr”）

成功的产物已经落盘了，有个别失败不用重跑整批。
